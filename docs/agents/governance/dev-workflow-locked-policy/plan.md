- **Area:** `governance`  ·  **Started:** 2026-09-29  ·  **Status:** In review

- **Next step:** Owner reviews PR `chore/dev-workflow-rules`, then squash-merge (branch auto-deletes). If wording on any policy point is off, it is corrected on the same branch before merge — points 1–10 are a locked owner decision, not open for re-litigation.
- **Roadmap initiative:** Locked dev-workflow policy in kit rules + every mirror.

## Goal

After this ships, every agent (Hermes/SME subagents, any agent) working in any repo that adopts this kit is told the identical dev-workflow policy the owner locked on 2026-09-29 — in the rule modules they actually read and in every generated tool-native mirror — instead of the old partial doctrine.

**Policy points encoded (owner-locked 2026-09-29, verbatim intent):**

1. Pre-flight (fetch --prune, status/branches/worktrees, open PRs, plan doc + worklog + code) before any work or planning; carry in-flight work, never parallel tracks.
2. Plan first: goal / phases / exit criteria in the plan doc, presented to the owner before code, in plain language.
3. Central plan doc = the `docs/agents/` spine (roadmap.md single plan doc, per-task fragments, worklog same-commit); small non-kit repos use one lightweight `docs/PLAN.md`; root-level PLAN.md forbidden; GitHub Issues never the plan home.
4. One branch per batch, cut from fresh origin/main; parallel writers get one worktree/clone each.
5. Push each batch as it completes (no single unreviewable dump).
6. STANDARD gate before merge: full tests + typecheck + lint + arch check, unfiltered, same session; independent SME re-review of non-trivial work; CI green as required check. Subagent self-report is not evidence.
7. Squash-merge to main only, branch deleted in the same operation; never merge-commit, never rebase-merge.
8. One open PR per repo at a time; no stacked PRs; branches exist only while work is live; owner-granted exceptions recorded in the plan doc.
9. Code + docs/worklog in the same commit (multi-commit PRs can fail `check-docs.sh --since` on intermediates).
10. Owner decisions presented as two tappable options + a recommendation, never prose blocks.

**Out of scope:** repo GitHub settings (squash-only + delete-branch-on-merge are already flipped centrally on all owned repos — nothing to change here); CI workflow edits (verify.yml already runs the mirror/doc/review gates this change leans on); the any agent-coverage initiative running in parallel on its own branch.
